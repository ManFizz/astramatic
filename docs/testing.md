# Как проверять

Сценарии с номерами лежат в [scenarios/](scenarios/README.md). У каждого указано, каким уровнем он проверяется.

## Перед коммитом

```bash
./gradlew verifyAll
```

Устройство не нужно. Запускает тесты логики, тесты `shared` и `desktopApp` и сравнивает скриншоты с эталонами. С нуля занимает около 45 секунд, после небольшой правки — около 20.

Перед release дополнительно собрать `:androidApp:assembleRelease` и проверить на телефоне: R8 тестами не покрыт.

## Уровни

| Уровень | Чем | Что проверяет | Где |
|---|---|---|---|
| Логика | JUnit + Robolectric | Правила без устройства | `androidApp/src/test`, `shared/src/commonTest` |
| Скриншот | Roborazzi + Robolectric | Как выглядят экраны и панели | `androidApp/src/test`, эталоны в `androidApp/src/test/screenshots` |
| Эмулятор | `tools/emu.sh` | Приложение целиком, включая VR-рендер | Вручную или скриптом |
| Шлем | Телефон пользователя | Комфорт, стерео, реальный уход центра | Только глазами |

## Скриншоты

Панели шлема снимаются с геометрией настоящего дисплея: 1280×800 при 240 dpi, видна только верхняя часть, как в `VrRenderer.PanelLayout`.

Изменили интерфейс намеренно — обновите эталоны и **посмотрите на картинки**, прежде чем коммитить:

```bash
./gradlew :androidApp:recordRoborazziDebug
```

Ограничения:

- Кнопки пульта в тестах подписаны числами (`4`, `82`), а не именами (`BACK`, `MENU`): в Robolectric нет этой таблицы. На устройстве имена настоящие.
- Эталоны сняты на Windows. На другой системе шрифты могут сгладиться иначе, поэтому при запуске в CI сравнение придётся настроить отдельно.
- Строка версии в тестах подменена через `LocalVersionText`: иначе хеш менял бы эталоны при каждом коммите.

## Эмулятор

В эмуляторе работает весь VR: оба глаза, линзовые искажения, панели, точка взгляда. В отличие от телефона, `adb screencap` здесь снимает и GL-картинку. Профиль `Medium_Phone_API_37.0` (x86_64) запускает сборку под arm64 через встроенную трансляцию, отдельная сборка Cardboard SDK не нужна.

```bash
tools/emu.sh start
```

```bash
tools/emu.sh install
```

```bash
tools/emu.sh vr
```

```bash
tools/emu.sh shot frame.png
```

Остальные команды: `key`, `tap`, `look`, `errors`, `stop`. Описание — в начале `tools/emu.sh`.

Что уже подтверждено вручную: запуск VR, «Назад» не выходит из VR, поворот головы, нажатие мимо панели, стрелки и OK в меню.

Ограничения:

- **Наведение взглядом неточное.** Поворот задаётся скоростью гироскопа, а задержки `adb emu` плавают. Надёжно попасть по кнопке пока можно только стрелками и OK. Для точного наведения нужна отладочная команда, она появится при разделении кода.
- **Компас подтягивает взгляд обратно.** Датчики компаса эмулятора не знают о заданном повороте, поэтому поправка медленно возвращает центр. Для точных измерений её стоит выключать.
- **Оси геймпада** через `adb` не подать: только кнопки.
- **Частота кадров и задержка** в эмуляторе не отражают телефон.
- В `start` профиль открывается только для чтения: установленные приложения и настройки после выключения не сохраняются.

## Только в шлеме

Перед release и после заметных правок рендера, около 10 минут:

- нет двоения при переводе взгляда с видео на меню и обратно;
- текст читается, уголки и ручка находятся без усилий;
- центр не уходит за несколько минут просмотра;
- настройка шлема в калибровочной комнате даёт прямые линии;
- пульт: нажатие, рецентр, перемотка стиком.
